# CGA 插件标准 v1.0.0

状态：待审批发布候选。与 SDK 1.0.0、审批规范 1.0.0 配套发布。
完整契约见[英文标准](CGA-Plugin-Standard-v1.0.0-en.md)。

## 支持边界

v1 仅支持可信、经过源码审查、与 CGA 同进程运行的第一方插件。
不提供第三方热加载、上传 ZIP 安装、插件市场、计费或进程沙箱。
现有插件不被强制停用，也不伪造历史审批。新插件和重大修改执行本标准。
宿主插件框架仍属于待发布的 CGA 源码工作，独立 SDK 不会给旧公开版自动补齐这些能力。
现有执行租约仅在单进程内生效，不构成多 worker 的分布式协调。
ADC、Audit、认证、项目授权、图/MCP、记忆、调度与备份仍为核心能力。
管理员安装/启用插件不等于批准插件发布。

## 必需契约

根目录必须有 `plugin.json`。拒绝未知字段。必须声明：

- `schema_version=1`、稳定的 snake_case `id`、名称和三段式版本；
- `sdk_api=cga.first-party.v1`、`execution_model=first-party-in-process`；
- 最低 CGA 版本、`module:execute` 入口、许可证及明确的资源文件；
- 最小权限、外联域名、密钥环境变量名称，不能包含密钥值；
- 1–180 秒超时、1–365 天保留策略及实际清理责任。

权限仅限 `project.read`、`activity.write`、`network.outbound`、
`secrets.read`、`filesystem.read`、`filesystem.write`、`scheduler.execute`。
外联和密钥权限必须配套声明具体域名和环境变量。禁止通配域名、带凭据 URL、
路径穿越、大小写冲突、符号链接和私钥文件。
JSON Schema 仅描述结构，仍须运行 SDK 语义及文件系统校验。

**权限声明不是运行时沙箱。** 同进程代码可以访问宿主权限，必须审查真实代码，
并在授权和 I/O 边界实施控制。最低版本声明不代表已经完成兼容性验证。

## 开发和运行要求

入口为 `execute(task, started_at, started_clock)`；使用 SDK 构造
`(state, response_status, payload, error)`。错误不能伪装成成功，JSON 结果不超过 64 KiB。
宿主负责认证、项目范围、启用检查、执行租约、调度、审计和持久化。
插件必须保持可选导入，不得破坏 core-only 分发。
禁用执行沿用 409、未打包路由沿用 404；执行期间不能强制卸载。

校验输入，限制超时、重试、输出和外联；不得输出凭据、原始配置或未脱敏响应。
保留策略必须真正实现并测试，不能只填数字。卸载默认保留配置、历史和恢复资料。
继续使用项目原端口，CGA 为 18001，不自动换端口、不停止无关服务。

界面复用现有插件管理规范，支持键盘操作和草稿保护；无修改时保存禁用。
报告图表支持明暗主题，失败与空数据必须区分。

## 验证和发布

提交授权、禁用/卸载租约、错误、超时、输出边界、密钥保护、保留、迁移、
回滚和平台兼容性测试。验证真实输出，不以按钮可点击代替 PDF 下载验证。
外部审计不可用、未执行和跳过的测试必须披露。

SDK 静态校验、显式文件打包和哈希不能代替审批。发布须遵循
[审批规范](CGA-Plugin-Approval-v1.0.0-zh.md)，标准、审批文件、SDK、Schema、
示例、指南和校验和一起交付。正式发布需有 GitHub 构建证明，不覆盖已发布版本。
本规范不替代 CGA API/Relay 原有签名与部署要求。
